# Credit Card Utilisation Management Simulator

Simulation-only educational/job-assignment prototype. It has no banking API, bank connection, payment processing, Direct Debit creation, or real-money movement.

## Mathematics (simple English)
Transfers move a balance between simulated cards. They do not remove debt. The roll-forward is: **opening debt + new spending + fees − simulated repayments − external payments − approved accounting adjustments = closing debt**. A transfer fee defaults to 0%. The £1,821 difference is a separate external-payment/accounting-adjustment requirement; it is never treated as money generated by cycling.

## গণিত (বাংলা)
ট্রান্সফার শুধু ঋণ এক কার্ড থেকে অন্য কার্ডে সরায়; ঋণ মুছে ফেলে না। হিসাব: **শুরুর ঋণ + নতুন খরচ + ফি − সিমুলেটেড পরিশোধ − বাইরের পেমেন্ট − অনুমোদিত অ্যাকাউন্টিং সমন্বয় = শেষের ঋণ**। ডিফল্ট ট্রান্সফার ফি ০%। £1,821 আলাদা বাইরের পেমেন্ট/অ্যাকাউন্টিং সমন্বয়; কার্ড ঘুরিয়ে তৈরি হওয়া টাকা নয়।

## Included in v0.2

- Editable simulated cards with validation and deletion
- Chronological monthly ledger with statements, spending, fees, repayments, adjustment and roll-forward checkpoints
- Feasibility engine and accounting reconciliation
- CSV, Excel workbook, plain-text report and print-to-PDF export
- 15 formula and accounting tests plus GitHub Actions CI

## Run
`npm install && npm run dev`  · tests: `npm test` · production build: `npm run build`

For the persistent local scenario API, build first and run `npm run serve`. It uses a local SQLite file (`server/simulator.sqlite`) and exposes only simulation scenario storage; it has no bank or payment integrations.

Barclays Rewards is configured with statement day 5 and Direct Debit day 30. Missing dates remain intentionally blank only for Santander A and Santander B statement dates. APR fields can be added later if interest is enabled.

## Financial Mathematics Lab

The app includes an educational lab for APR-to-EAR conversion, Actual/365 daily interest, fixed-payment annuities, payoff duration, and amortisation schedules. Advanced risk methods such as stochastic calculus, PDEs, copulas, and Monte Carlo are documented as optional portfolio-risk concepts rather than being misrepresented as ordinary card-ledger calculations.
